01

BoilerPark

Availability-aware parking guidance for Purdue commuters. A CS 475 Human-Computer Interaction team project helping students, faculty, and staff find open, permit-eligible parking near their destination without circling lots or risking citations.

Read project details
  • Ran semi-structured needfinding interviews in a 10-participant study (8 students, 2 staff) covering commuting routines, permit confusion, event-day disruptions, and trust in estimated availability.
  • Synthesized 126 interview notes into an affinity diagram of 7 themes and 21 subthemes, finding that drivers value availability over proximity, want 1–3 backup lots, and need to see how fresh the data is.
  • Built personas, storyboards, and user flows, then a 9-screen paper prototype covering 4 core tasks: permit-aware recommendations, game-day restriction alerts, rules lookup linked to official Purdue sources, and one-tap rerouting when a lot is full.

Five-person team. Next: interactive digital prototype, cognitive walkthrough, and usability testing.

Sentiment Analysis Platform

A full-stack market sentiment platform that fetches financial news, applies FinBERT-based sentiment analysis, and visualizes daily sentiment trends through an interactive dashboard.

Read project details
  • Helps users quickly see whether media coverage of a public company has been trending positive, negative, or neutral.
  • FastAPI backend with PostgreSQL and Docker to store and retrieve historical sentiment results efficiently.
  • Lightweight HTML, JavaScript, and Chart.js frontend showing daily average sentiment.

03

Campus Event Management System

A deployed full-stack campus event platform where students discover events, manage RSVPs, and leave feedback, while club admins create events and analyze attendance.

Read project details
  • Relational MySQL schema for users, clubs, events, locations, RSVPs, and feedback using foreign keys and SQLAlchemy models.
  • Role-based authentication, event CRUD, room conflict detection, RSVP capacity enforcement, and reporting dashboards.
  • Database transactions and row-level locking stop concurrent users from claiming the same final seat.
